# M6.4: lanes per project, one VM runner, docs of the current state

Go for the spec: owner, 2026-10-27 ("we should never share lanes between projects. They are specific to a project. Never reuse and scope per project"; lanes declared in the member's own `ciburst.json`; no ciburst limits beyond Scaleway's; "Drop vmFirst"; "We do not have pools, we have a generic serverless runner and a vm runner"; "Reorganize the project documentation completely to reflect the current state"). Spec D60 to D64. Base commit: named in each agent prompt.

## Goal

A fleet shares one thing between projects: the VM runner. Everything that names a job belongs to the project that owns the job: its lanes, its `ignoreJobs`. A lane of one project can never take, route or be reused by another project's job. The docs describe this state and nothing else.

## Terms

- **VM runner:** the fleet's VMs (Scaleway Instances or Hetzner), Docker executor, shared by every member (D59).
- **Lane:** one project's Serverless Jobs definition for one image and size, with that project's runner and tag. The serverless side of ciburst is the set of lanes of all projects.
- **Project config:** a project's own `ciburst.json`; the host's also holds the fleet settings.

## Rules

R1. Configuration.
- Fleet settings, in the host's `ciburst.json` only: `name`, `gitlab`, `host`, `provider`, `providers`, `cache`, and `vm`, one object: `tag` (default `vm`), `runtime`, `image`, `slots`, `instanceTypes`, `maxRuns`, `maxQueueS`, `warmStart`.
- Project settings, in every project's `ciburst.json`, host included: `lanes` (array: `tag`, `image`, `jobs`, `vcpu`, `memoryMiB`, `storageMiB`, `timeoutS`, `waitTimeoutS`, `maxRuns`) and `ignoreJobs`.
- `pools`, `defaultPool`, `stages`, `vmFirst`, `spillRunner` are refused with a message that names the replacement. No migration code: the three deployments (demo, the drill consumer, the production host) change their files.
- A member's `ciburst.json` with a fleet setting is refused by `ciburst-join`, naming the key.

R2. Routing, per project.
- A pending job of project P: a match in P's `ignoreJobs` starts nothing; else the first of P's lanes with a `jobs` pattern matching the name gets a lane run; else the VM runner takes it.
- Patterns of another project never apply to P. Two projects may use the same lane tag and the same patterns.
- No stage routing.

R3. Lane resources, per project.
- Job definition `<name>-<project id>-<tag>`, environment as today plus `CIBURST_PROJECT`.
- One GitLab runner per lane, registered in its project only, tag = the lane tag, `run_untagged false`.
- Live runs and `maxRuns` count per definition, so per project and lane.
- No ciburst cap across projects; Scaleway's limits apply (6 vCPU, 16 GB, 400 concurrent runs per organization).

R4. Host lanes: `ciburst-setup` creates, updates and deletes the host's definitions and runners with the owner key, as today.

R5. Member lanes.
- `ciburst-join` reads the member's `ciburst.json`, validates it, registers one runner per lane in the member project, and posts the lanes, the runner tokens and `ignoreJobs` to `/join`.
- `/join` creates or updates the member's definitions with the dispatch key, deletes the member's definitions that are no longer listed, and stores the record. It answers within GitLab's and the function's limits (30 s), else it fails with the step that did not finish.
- A lane change in a member takes effect with a new `ciburst-join`. Joining needs a valid code, as today.
- `/leave` and `ciburst-leave` delete the member's definitions, runners, webhook and record.
- `ciburst-destroy` deletes every member's definitions with the deployment.

R6. Member record: project id, webhook secret, VM runner token, and per lane its tag, definition id and runner token; `ignoreJobs` and the lane routing (`tag`, `jobs`, `maxRuns`) in clear text; secrets sealed as today.

R7. No vmFirst, no spill.
- The VM runner carries only its own tag. The spill runner, the spill queue and the spill fallback go.
- Warm start keeps its VM part; its lane rule (lanes leave slots free) goes.

R8. Tools.
- `ciburst check` checks each project against its own lanes and `ignoreJobs`: a lane job without the lane's tag, with another `image:`, or with a Docker need; a VM job with a lane tag.
- `check --suggest` prints lanes for the checked project.
- `ciburst status` lists lanes per member.

R9. Docs: the current state only.
- `docs/SPEC.md`: the decision log holds the decisions in force, each stating the current state. Superseded decisions become one row each in a second table, "Dropped", with the reason only. No narrative of how a decision changed.
- The milestone contracts are folded into the spec: their rules in force move into the sections they govern; `docs/milestones/` is removed together with the code citations `M<n> rule R<k>`, which become spec references (`spec 6.3`, `D60`).
- Terms across README, AGENTS.md, SPEC, RUNBOOK, PROVIDERS, the component and the CLI help: "VM runner" and "lane". No "pool" in user-facing text. The runbook keeps procedures and measured results; drill logs that only explain superseded behavior go.
